# FormulaD MES 2.0 — MVP 0.1 (DEMO)

Локальный демонстрационный стенд: ASP.NET Core (.NET 10) API только на чтение + React/TypeScript UI на русском языке.
**Данные синтетические** (`fixtures/production-plan.demo.json`). Подключения к PROD `SQLACCESS` / базе `FormulaD` нет
и в этом MVP не предусмотрено.

## Что умеет

- Экран «Производственный план»: таблица, поиск по началу или последним цифрам VIN (клавиатура и сканер),
  фильтр по статусу, пагинация,
  состояния «Загрузка», «Ничего не найдено», «Нет доступа», «Нет связи с сервером».
- Карточка изделия только для чтения (Enter при полном VIN или клик по строке).
- API `GET /api/v1/...` по `docs/API_CONTRACT.md`.
- Изменение порядка запуска (стрелки, `Alt+↑/↓`, перенос на позицию) — **только на демо-данных
  в памяти**: маршрут записи создаётся лишь при `DataSource=Demo` и пропадает вместе с перезапуском.
  В SQL-режиме операций записи нет вообще.
- Экран «Несоответствия» (NCP): список с фильтром по VIN/статусу, регистрация (VIN, станция,
  компонент, количество, тип, комментарий оператора), раздельные действия «деталь установлена/
  заменена» и «закрыть заявку» — это разные состояния, а не одно (см. `docs/SPECIFICATION.md`,
  раздел 16). Тоже только демо-данные.
- Журнал событий: кто, когда и что изменил — для перестановки плана и всех операций NCP.
- Экраны «Старт», «Завершение», «FOK»: переходы 0→1→2→3 по сканеру (тот же компонент
  переиспользован трижды). FOK дополнительно проверяет незакрытую обязательную деталь
  (по данным NCP) и показывает причину отказа уже при сканировании, не только после попытки
  подтвердить. Тоже только демо-данные.
- Экран «Станции»: визуальная линия из 11 станций со своей цветовой схемой (серый/синий/
  зелёный/жёлтый/красный — отдельная от бейджей плана семантика), ленточный список компонентов
  станции с отметкой «проверено» (кто/когда), массовые действия «Проверено всё»/«Снять проверку»,
  «Зафиксировать расхождение» открывает форму NCP с готовыми VIN/станцией/компонентом. Тоже
  только демо-данные.
- Экран «Rework»: переход 2→4 («Отправить в Rework» — кнопка на экране FOK, когда изделие
  заблокировано незакрытой деталью) и 4→2 («Завершить Rework», с той же проверкой обязательной
  детали, что у FOK). Открытые NCP изделия видны и управляются прямо в карточке Rework (деталь
  установлена, закрыть заявку) — без перехода на отдельный экран. Тоже только демо-данные.
- Печать JobCard с QR (генерируется в браузере, кодирует VIN): одна карточка по двойному
  клику на строке плана или кнопкой в карточке изделия, пакетная печать по чекбоксам в плане
  + «Выбрать первые 12» + «Печать выбранных». Печать отмечает дату печати изделия, статус
  не меняет. Тоже только демо-данные.
- Экран «Импорт плана»: файл CSV/TSV или вставка диапазона из Excel → построчная проверка (все
  ошибки сразу, не первая попавшаяся) → исправление прямо в ячейке или через справочник
  (модель/цвет/комплектация) с повторной проверкой → публикация в конец очереди (кнопка активна
  только при нуле ошибок). Тоже только демо-данные.
- Dev-аутентификация: включается явно, только в Development, только на loopback, пароль — из env/user-secrets.
- Два источника данных: `Demo` (фикстуры, по умолчанию) и `Sql` — только отдельный TEST-экземпляр SQL Server
  с учётной записью на `SELECT`.

## Требования

- .NET SDK 10.0
- Node.js 20+ (проверено на 22)

## Запуск (macOS / Linux)

### 1. API

```bash
cd src/FormulaD.Mes.Api
dotnet user-secrets set "DevAuth:Password" "<придумайте локальный пароль>"
DevAuth__Enabled=true DevAuth__Username=demo-operator ASPNETCORE_ENVIRONMENT=Development dotnet run
```

Ожидаемо: API слушает `http://localhost:5080`, в логе — `Now listening on: http://localhost:5080`.
Если `DevAuth:Password` не задан, в логе будет предупреждение, вход невозможен, а защищённые эндпоинты отвечают `401`.

Проверка без UI:

```bash
curl -s http://localhost:5080/api/v1/health/live          # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' \
     http://localhost:5080/api/v1/production-plan          # 401
```

### 2. UI

```bash
cd apps/web
npm install
npm run dev
```

Открыть `http://localhost:5173`, войти под `demo-operator` и заданным паролем. Vite проксирует `/api` на `http://localhost:5080`.

### Остановка

`Ctrl+C` в каждом терминале. Фоновых служб, портов брандмауэра и установок в систему проект не создаёт.

## Режим SQL (TEST-экземпляр)

Включается только явно и только против отдельной тестовой базы. PROD-хост `SQLACCESS`, база `FormulaD`
и админские логины (`sa`, `sa1`) отклоняются на старте.

```bash
cd src/FormulaD.Mes.Api
dotnet user-secrets set "Sql:ConnectionString" \
  "Server=<test-host>;Database=<TEST-db>;User ID=<readonly-login>;Password=<...>;Encrypt=True"
DataSource=Sql Sql__IsTestEnvironment=true dotnet run
```

Поиск по VIN выбирает режим по виду ввода: только цифры — поиск по последним цифрам VIN (`LIKE '%123'`,
выполняется сканом), любой другой ввод — поиск по началу (`LIKE 'ABC%'`, использует индекс по `VIN`).
Путь сканера остаётся быстрым. Поиск по середине VIN не поддерживается.
Запросы — параметризованные `SELECT` с явным белым списком колонок, пагинацией `OFFSET/FETCH`, без `NOLOCK`
и без динамических имён объектов. Подключение не открывается, пока конфигурация не прошла проверки.
Приложение не содержит кода изменения данных; гарантию даёт TEST-логин только с правом `SELECT`.


## Структура

```text
src/FormulaD.Mes.Api/      ASP.NET Core Minimal API (домен + чтение + endpoints)
tests/                     интеграционные тесты API (xunit)
apps/web/                  React + TypeScript + Vite
fixtures/                  синтетические записи плана
sql/                       только шаблоны SELECT для будущей TEST-интеграции
docs/                      требования, контракты и отчёт о реализации
```

## Ограничения

MVP 0.1 — не промышленная MES. Нет входного контроля (packing lists), отчётности и
реальных учётных записей. Подробности — `docs/IMPLEMENTATION_REPORT.md`.
