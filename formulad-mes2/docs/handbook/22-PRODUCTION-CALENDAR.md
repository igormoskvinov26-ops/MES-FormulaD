# 22. Производственный календарь

> **Назначение:** концепция, согласованные решения, алгоритм и план этапов блока «Календарь».
> **Состояние на 2026-11-06:** выполнены этап 1–3 и доработки. Не сделано: лист контроля с галочками и такт по моделям.
> **Происхождение:** идея владельца, проработана в обсуждении.

## 1. Концепция

Календарь **рассчитывается**, а не хранится. Вход: очередь плана, производительность линии и график работы. Выход: день и время прогнозируемого выпуска для каждого изделия.

## 2. Согласованные решения

| № | Решение | Принято |
|---|---|---|
| 1 | Одна смена 08:00–17:00, обед 12:00–13:00, пн–пт, праздники подставляет владелец | да |
| 2 | Производительность — одно число «изделий в смену» (8); такт по моделям — позже | да |
| 3 | Перетаскивание меняет только порядок (`SEQN`); плановые даты не трогаются | да |
| 4 | Двигать можно только запланированные; начатые, собранные и Rework закреплены | да |
| 5 | Последняя станция с полностью отмеченными компонентами, следующая — «в работе» | да |
| 6 | Три поста контроля качества между станциями; места ещё не указаны | вопрос открыт |

## 3. Алгоритм

1. Изделия без ФОК (`statusId = 3`). Пустой статус — запланированное.
2. Порядок: начатые (закреплены), затем запланированные по `SEQN`.
3. Слоты: `perShift` равномерно по рабочему времени смены.
4. Первый свободный слот — сегодня, не раньше текущего времени.
5. Отклонение: `прогноз − плановая дата` в календарных днях.

## 4а. Выходные, праздники, особые часы

Отметка по дате: **выходной** (`off`) или **рабочий** (`work`) — перенесённый или с особыми часами. API — [04-API-REFERENCE](04-API-REFERENCE.md).

В шапке дня кнопка ⚙ открывает «Настройка дня»: галочка «Праздник», часы «Рабочий день с ... до ...», примечание. «ОК» запоминает изменение; появляется панель «Изменений календаря: N» с кнопкой **«Пересчитать план»**.

**Администрирование → Производственный календарь.** Загрузка из Excel (CSV/TSV): дата, тип, необязательные часы, примечание. Ручное добавление и удаление отметок по годам.

## 4а-1. График работы линии

«Администрирование → Производственный календарь → График работы»: смена, изделий в смену, рабочие дни, до 4 перерывов. Форма проверяет данные до отправки теми же правилами, что сервер. Такт по моделям пока не поддержан.

## 4б. Ракурсы и «Прогресс сборки»

- **День:** почасовая сетка, изделия в часах своих слотов.
- **Месяц:** сетка пн–вс; в клетке число, загрузка, до 3 изделий; клик по клетке → «День».
- **Прогресс сборки** — клик по карточке: линия станций, квадроцикл на текущей станции (`lineProgress.ts`). Посты контроля показываются, когда заданы.

## 4в. Перенос карточек

Меняет порядок (`SEQN`) через `POST /production-plan/{vin}/move`. Плановые даты не меняются.

- **Перетащить** в «Дне» и «Неделе»; **Alt+↑/↓** без мыши.
- **Подтверждение** последствий до выполнения.
- **Откат** последнего переноса на странице.
- **Не сделано:** перенос в «Месяце»; нативный drag-and-drop на планшете.

## 4г. Доработки

- **Посты контроля качества:** название (до 40 символов), станция; до 10 постов; показываются пунктирным блоком на линии.
- **История выпуска:** изделия с ФОК в прошлых днях (метка «выпущено», отклонение).
- **Перенос кнопками:** кнопка «⋮» — «В начало», «Выше», «Ниже», «В конец».
- **Формат «год × месяцы»:** загрузка матрицы (напр. со 'N*' = сокращённый); на файле с официального сайта не проверялся.

## 6. Известные ограничения

- Плановые даты не используются для раскладки, только для сравнения.
- В Sql-режиме календарь в JSON-файле; перенос в базу — вместе с миграциями (T-029).
- На планшете: перетаскивание не работает; есть Alt-перенос и кнопки «⋮».
