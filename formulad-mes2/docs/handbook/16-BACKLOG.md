## 1. Как читать бэклог

**Приоритеты**

| Код | Смысл |
|---|---|
| **P0** | Блокирует пилот: без этого запускать на реальных операторах нельзя (безопасность, потеря данных, ложные данные на экране). |
| **P1** | Нужно до пилота: пилот возможен без этого лишь с явным принятием риска или обходным приёмом. |
| **P2** | После пилота / по результатам обратной связи. |

**Размер:** S — до 1–2 дней, M — до недели, L — больше недели или требует решения вне команды. Это относительные размеры, **не обещание сроков** (оценки по предприятию — `<определить: оценки команды>`).

**Типы:** `функционал`, `техдолг`, `UX`, `безопасность`, `данные`, `ops`, `тесты`, `доки`, `интеграция`.

**Идентификаторы:** `EPIC-NN` — эпик; `T-NNN` — задача. Ссылки вида `В-NN` — открытые вопросы спецификации ([SPECIFICATION.md](../SPECIFICATION.md), раздел 30); `OQ-N` — вопросы из [OPEN_QUESTIONS.md](../OPEN_QUESTIONS.md); `И-NN` — вопросы по 1С из [INTEGRATION_1C.md](../INTEGRATION_1C.md); `R-NN` — риски AS-IS из [SPRINT00_ACCESS_AUDIT.md](../SPRINT00_ACCESS_AUDIT.md); `AT-NN` — сквозные критерии приёмки спецификации (раздел 29).

**Важное ограничение для всего бэклога.** Подключение приложения к PROD (`SQLACCESS` / база `FormulaD`) — **постоянный запрет** владельца (см. [17-PRODUCTION-CUTOVER-PLAN](17-PRODUCTION-CUTOVER-PLAN.md), раздел 2). Ни одна задача ниже не требует такого подключения, если не сказано иначе; задачи, которые его потребовали бы, помечены «⛔ после решения владельца».

## Definition of Ready / Done

### Definition of Ready (задача готова к взятию)

- [ ] Есть ID, приоритет, размер, критерии приёмки (проверяемые, без «улучшить»).
- [ ] Нет блокирующего открытого вопроса `В-NN`/`OQ-N`/`И-NN`, либо вопрос явно входит в задачу как её первая часть.
- [ ] Указаны затронутые файлы/модули и тесты, которые придётся дописать.
- [ ] Для задач с данными: определено, на какой среде проверяется (Demo / изолированная TEST) — **не PROD**.
- [ ] Для UX: есть эталон (лист ассетов, скриншот «до», целевое поведение) и устройства проверки.
- [ ] Для безопасности: оценено влияние на запрет PROD и на секреты.

### Definition of Done (задача закрыта)

- [ ] Критерии приёмки выполнены и показаны (тест, скриншот, лог).
- [ ] `dotnet build`, `dotnet test`, `npm run test`, `npx tsc --noEmit` проходят ([10-TESTING](10-TESTING.md)); CI зелёный (после T-090).
- [ ] Новые правила покрыты тестами на обоих режимах данных (Demo и Sql-тесты без сервера; интеграционные — после T-021).
- [ ] Контракты `aria-label`, на которые опираются тесты, не сломаны ([07-FRONTEND-GUIDE](07-FRONTEND-GUIDE.md)).
- [ ] Обе темы (светлая/тёмная) проверены; для терминальных экранов — планшетный размер.
- [ ] Нет секретов, строк подключения и обращений к `FormulaD` ([09-SECURITY](09-SECURITY-AND-CONSTRAINTS.md)); `git status` без лишнего.
- [ ] Документация обновлена: [04-API-REFERENCE](04-API-REFERENCE.md), [03-DOMAIN-MODEL](03-DOMAIN-MODEL.md) или [07-FRONTEND-GUIDE](07-FRONTEND-GUIDE.md) — по затронутому; `*.png` добавлены через `git add -f`.
- [ ] Для операций записи: запись в журнал событий, идемпотентность и откат проверены.
- [ ] Ревью выполнено другим человеком (для безопасности и SQL — обязательно независимое, OQ-10).
