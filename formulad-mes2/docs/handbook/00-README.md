## 1. Что это за пакет

**FormulaD MES 2.0** — веб-система управления производством (MES) для сборки квадроциклов: производственный план,
сканирование JobCard (запуск → завершение → Final OK), станции и проверка комплектующих, несоответствия (NCP) и
Rework, входной контроль поставок, отчётность. Она проектируется как замена/надстройка над действующим решением
на **MS Access + SQL Server** (подробности — [01](01-PRODUCT-AND-REQUIREMENTS.md)).

Состав кода (всё внутри `formulad-mes2/`):

| Путь | Что | Технологии |
|---|---|---|
| `src/FormulaD.Mes.Api/` | Backend: REST API + раздача собранного UI | ASP.NET Core Minimal API, .NET 10, `Microsoft.Data.SqlClient` |
| `apps/web/` | Frontend: SPA на русском | React 18, TypeScript 5.6, Vite 5, vitest |
| `tests/FormulaD.Mes.Api.Tests/` | Интеграционные тесты API | xUnit, `WebApplicationFactory` |
| `fixtures/` | Синтетические демо-данные (JSON) | — |
| `sql/` | SQL-скрипты и шаблоны для TEST-базы | T-SQL |
| `stand/stand.sh` | Тестовый стенд одной командой | bash |
| `deploy/` | Шаблоны развёртывания как службы Windows | bat, json |
| `docs/` | Исторические документы проекта (ТЗ, контракты, планы) | Markdown |
| `docs/handbook/` | **Этот справочник** | Markdown |

Система работает в двух режимах данных: **Demo** (фикстуры в памяти процесса, по умолчанию) и **Sql** (только
тестовая база `FormulaD_TEST`). Рабочая база `FormulaD` (PROD) **не подключается никогда** — см.
[09-SECURITY-AND-CONSTRAINTS](09-SECURITY-AND-CONSTRAINTS.md).

## 3. Быстрый старт за 10 минут

Нужно: **.NET SDK 10**, **Node.js 20+**, `curl`. SQL Server **не нужен**. Проверка: `dotnet --version`, `node --version`.

### Вариант A — стенд одной командой (рекомендуется)

```bash
cd formulad-mes2
chmod +x stand/stand.sh      # один раз
./stand/stand.sh up          # соберёт UI и API, запустит, напечатает логин и пароль
./stand/stand.sh smoke       # 11 проверок живого стенда
./stand/stand.sh down        # остановка
```

После `up` откройте `http://localhost:5080`, войдите с напечатанными логином (`demo-operator`) и паролем
(генерируется заново при каждом запуске, лежит в `stand/.run/credentials`). Первая сборка занимает пару минут
(скачиваются npm-пакеты). Подробности и подводные камни — [11](11-OPERATIONS-AND-STAND.md#2-тестовый-стенд-standsh).

### Вариант B — вручную, с горячей перезагрузкой UI

Два терминала.

```bash
# Терминал 1 — API на http://localhost:5080
cd formulad-mes2/src/FormulaD.Mes.Api
DevAuth__Enabled=true DevAuth__Username=demo-operator DevAuth__Password='<любой-локальный-пароль>' \
ASPNETCORE_ENVIRONMENT=Development dotnet run

# Терминал 2 — UI на http://localhost:5173 (Vite проксирует /api на :5080)
cd formulad-mes2/apps/web
npm install
npm run dev
```

Пароль можно хранить в user-secrets вместо переменной окружения:
`dotnet user-secrets set "DevAuth:Password" "<пароль>" --project src/FormulaD.Mes.Api`.
Без пароля вход невозможен, а все бизнес-эндпоинты отвечают `401` — это штатная защита (см. [09](09-SECURITY-AND-CONSTRAINTS.md#3-dev-аутентификация)).

### Проверка, что всё работает

```bash
curl -s http://localhost:5080/api/v1/health/live        # {"status":"ok"}
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:5080/api/v1/production-plan   # 401 без входа
cd formulad-mes2/apps/web && npx vitest run              # 61 тест
cd formulad-mes2 && dotnet test tests/FormulaD.Mes.Api.Tests   # 158 тестов
```

## 4. Что посмотреть руками (сценарий на демо-данных)

Демо-данные: 6 изделий `DEMO-VIN-00001…00006` (разные статусы, один неизвестный, один без статуса), 5 заявок NCP,
11 станций, 8 компонентов, 3 поставщика. Состояние хранится **в памяти процесса** — перезапуск возвращает всё к
исходному. Сканер эмулируется вводом VIN и Enter.

| Шаг | Куда нажать | Что должно произойти |
|---|---|---|
| 1 | **Производственный план** | таблица из 6 строк, плитки сводки (всего/запланировано/в работе/…), фильтры, цветные состояния. Двойной клик по строке — печатная JobCard с QR |
| 2 | **Старт** → ввести `DEMO-VIN-00002`, Enter | карточка изделия (статус «Запланировано»); повторный Enter с тем же VIN → переход **0 → 1** |
| 3 | **Завершение** → `DEMO-VIN-00001`, Enter, Enter | переход **1 → 2** (блокировки по NCP здесь нет — так согласовано спецификацией) |
| 4 | **FOK** → `DEMO-VIN-00003`, Enter | зелёный сигнал «готово к подтверждению»; кнопка «Подтвердить FOK» открывает модальное окно → **2 → 3** |
| 5 | **FOK** → `DEMO-VIN-00001`, Enter | красный сигнал «FOK заблокирован»: открыты NC-2026-0001/0002 с неустановленной деталью; доступна кнопка «Отправить в Rework» → **2 → 4** |
| 6 | **Rework** → `DEMO-VIN-00001` | в карточке открытые NCP: «деталь установлена» → «закрыть заявку» → «Завершить Rework» → **4 → 2**; изделие снова в очереди FOK |
| 7 | **Станции** → `DEMO-VIN-00001` | линия из 11 плиток; красные — станции с открытыми NCP; клик по станции — компоненты, «Проверено всё», «Зафиксировать расхождение» |
| 8 | **Несоответствия** | список NCP, регистрация нового, печать NCP-листа |
| 9 | **Импорт плана** | вставка из Excel → построчная проверка → публикация в конец очереди |
| 10 | **Входной контроль** | «Новая поставка» → вставка Packing List → коробки → результаты по строкам → закрытие |
| 11 | **Отчётность**, **Администрирование** | сводки; справочники только для чтения |

Также: переключатель темы (светлая/тёмная) и кнопка сворачивания бокового меню — внизу бокового меню.

## 5. Глоссарий

| Термин | Значение |
|---|---|
| **MES** | Manufacturing Execution System — система оперативного управления производством |
| **VIN** | Идентификационный номер изделия; **первичный ключ** `dbo.tblProductionPlan`; в демо — `DEMO-VIN-0000N` |
| **Производственный план** | Очередь изделий к выпуску (таблица `tblProductionPlan`), порядок задаётся полем `SEQN` |
| **JobCard** | Печатная карточка изделия с QR-кодом (кодирует VIN); по её сканированию идут все переходы |
| **Статус 0–4** | `0` Запланировано → `1` В работе → `2` Производство завершено → `3` FOK пройден; `4` Rework |
| **Старт / Завершение / FOK** | Три экрана-перехода по сканеру: `0→1`, `1→2`, `2→3` |
| **FOK / Final OK** | Финальное подтверждение готовности изделия; запрещено при неустановленной обязательной детали |
| **Rework** | Доработка вне линии (статус `4`); выход `4→2` вручную после закрытия проблем |
| **NCP** | Non-Conformance Protocol — заявка о несоответствии (брак / пересорт / недостача) по детали изделия |
| **PartInstalled** | Признак «правильная деталь установлена» — отдельно от статуса заявки; именно он блокирует FOK |
| **Cripple («крипл»)** | Изделие с необходимой, но не установленной деталью |
| **Red Table / Green Table** | Физические столы для разбора брака; автоматизация решений о ремонте/списании — вне объёма |
| **Станция (СТ)** | Рабочее место линии; в актуальной схеме **11 станций** (СТ1–СТ11) + точки ОТК |
| **ОТК** | Отдел технического контроля; контрольные точки между группами станций |
| **Проверка компонента** | Отметка «проверено» по компоненту станции (кто/когда); не равна «деталь установлена» |
| **Входной контроль (IQC)** | Приёмка комплектующих: поставка → упаковки → строки Packing List → результат OK/брак/пересорт/недостача |
| **Packing List** | Упаковочный лист поставщика; вставляется в экран из Excel |
| **HU** | Handling Unit — номер упаковки (коробки), штрихкод для открытия коробки сканером |
| **Норматив контроля** | Доля (%) или штуки от строки, подлежащая проверке; по умолчанию 100 % |
| **Demo** | Режим данных: JSON-фикстуры в памяти, записи пропадают при перезапуске |
| **Sql** | Режим данных: реальные таблицы **TEST-базы** `FormulaD_TEST` |
| **TEST / PROD** | `FormulaD_TEST` — тестовая база; `FormulaD` — рабочая база (на сервере `SQLACCESS`). К PROD подключаться **запрещено** |
| **SQLACCESS** | Имя сервера (ВМ Windows Server 2019), на котором стоят и PROD-, и TEST-база |
| **DevAuth** | Временная dev-аутентификация (логин/пароль из окружения), только в Development и только с loopback |
| **Стенд** | Локальный запуск на демо-данных (`stand/stand.sh`) |
| **F7** | Бренд и дизайн-система интерфейса (графит + красный, косые/срезанные формы) |
| **[С] / [П] / [В] / [Б]** | Пометки в `SPECIFICATION.md`: согласовано / проектная рекомендация / открытый вопрос / будущий этап |
| **В-NN** | Номер открытого вопроса в `SPECIFICATION.md` (раздел 30) |
| **AC / QA / AT** | Критерии приёмки: `AC`, `QA` — `ACCEPTANCE.md` (MVP 0.1); `AT` — раздел 29 спецификации |

## 7. Три вещи, которые нельзя не знать

1. **PROD не трогаем.** База `FormulaD` — рабочая, подтверждённого резервного копирования нет. Допустима только
   `FormulaD_TEST`. Защита в коде — по имени базы, логину и флагу `Sql:IsTestEnvironment` (раздел 1 документа 09).
2. **Документы `docs/*.md` могут отставать от кода.** Если они спорят с кодом, верьте коду и поправьте документ.
3. **Секреты не коммитим.** Ни паролей, ни строк подключения, ни `.env`. Пароль стенда генерируется и не попадает в git.
