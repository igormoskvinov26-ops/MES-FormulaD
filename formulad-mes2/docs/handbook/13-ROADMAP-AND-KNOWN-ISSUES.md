## 1. Что реализовано

Этапы `DEVELOPMENT_PLAN.md` **1–10 завершены** (27.10.2026); все модули работают на SQL Server (Development — `FormulaD_TEST`, Production — `FormulaD`).
Легенда: ✅ есть · ⚠ есть, но с оговоркой · — нет.

| Модуль | SQL | Оговорки |
|---|---|---|
| Производственный план (таблица, поиск, фильтры, карточка) | ✅ | Поиск по последним цифрам — скан таблицы; на живом SQL не измерялся |
| Перестановка порядка | ✅ | Сохранение каждого шага (решение РП); нет `rowversion` |
| JobCard + QR, пакетная печать | ✅ | Макет не согласован (В-12); печать браузерная |
| Импорт плана (CSV/TSV, вставка) | ✅ | `.xlsx` напрямую не поддерживается |
| Старт `0→1`, Завершение `1→2` | ✅ | Строки `Status` — сверить с реальными данными (`ponytail` в `SqlPlanTransitions`) |
| FOK `2→3` | ⚠ | Семантика блокировки отличается (см. 2.2) |
| Rework `2→4`, `4→2` | ✅ | Критерии закрытия — В-22/В-23 |
| Станции (линия, проверки, расхождения) | ✅ | Таблицы создаёт приложение (DDL-права); ОТК/инспекторы — нет |
| NCP (регистрация, доустановка, закрытие, печать) | ⚠ | Нет `PartInstalled`, один 50-символьный `Comment` (см. 2.2) |
| Входной контроль (поставки, Packing List, HU, нормативы, закрытие) | ✅ | Таблицы создаёт приложение; недопуск брака в производство — нет (В-33) |
| Отчётность (сводки) | ✅ | Только агрегаты; без периодов/выгрузок; экран переоформлен в F7 (2026-11-04) |
| Администрирование (справочники) | ✅ | Редактирования нет |
| Журнал событий | ⚠ | В памяти; не хранится, наружу не отдаётся |
| Аутентификация | DevAuth | Нет ролей и корпоративного входа |
| Тестовый стенд | ✅ | `stand/stand.sh` |
| Интерфейс F7 (тёмная/светлая тема, сворачиваемое меню, анимация кнопок) | ✅ | Все экраны переоформлены (этапы 1–3, скан-экраны, Отчётность и Импорт; 2026-11-04) |

**Хронология (по истории git).** MVP 0.1 и этапы 1–10 → скрипты копирования схемы и данных PROD→TEST (`sql/`), раздача SPA из
`wwwroot` и поддержка службы Windows (`UseWindowsService`, `install-service.bat`) → SQL-адаптеры для TEST (`SqlPlanTransitions`,
`SqlPlanOrderEditor`, `SqlJobCardPrinter`, `SqlPlanPublisher`, `SqlNcpStore`, `SqlStationChecks`, `SqlPlanImport`, `SqlIncomingInspection`)
→ полировка интерфейса и тёмная тема → редизайн в стиле F7 (экраны, боковое меню, анимации) → тестовый стенд.

## 2. Известные проблемы

Серьёзность: **Крит** — блокирует эксплуатацию/безопасность; **Выс** — ломает корректность; **Ср** — неудобство/долг; **Низ** — косметика.

### 2.1. Безопасность и эксплуатация

| № | Серьёзность | Проблема | Подробнее |
|---|---|---|---|
| K-01 | Крит | **SQL-режим ни разу не выполнялся против живой TEST-БД в этой среде** (SQL Server недоступен). Проверены конфигурация, тексты запросов, маршруты; сами запросы — нет | [02](02-ARCHITECTURE.md#10-ограничения-и-компромиссы) |
| K-02 | Крит | **Нет ролей и корпоративной аутентификации**; любой вошедший делает всё; DevAuth работает только на loopback | [09](09-SECURITY-AND-CONSTRAINTS.md#3-dev-аутентификация) |
| K-03 | Крит | **R-001:** у PROD нет подтверждённого резервного копирования (вне кода; блокирует любое обсуждение PROD) | [09](09-SECURITY-AND-CONSTRAINTS.md#1-постоянный-запрет-на-prod) |
| K-04 | Крит | **Развёртывание службой Windows не работоспособно «из коробки»:** в Production DevAuth выключен (вход невозможен), `AllowedHosts`/loopback закрывают доступ с других ПК, служба под `LocalSystem`, нет скрипта публикации | [11](11-OPERATIONS-AND-STAND.md#4-развёртывание-как-служба-windows) |
| B-01 | Выс | **Журнал событий хранится в памяти** и не виден пользователю: «кто что сделал» теряется при перезапуске | `EventLog.cs` |
| B-02 | Выс | **Нет конкуренции правок:** `rowversion` не используется; перестановка и правки NCP — «последний записал» (AT-30); нет идемпотентности (AT-29) | |
| B-03 | Выс | Защита от PROD держится на имени базы/логине/флаге; проверка **хоста убрана**, т.к. TEST на том же экземпляре; права логина не проверены | [09](09-SECURITY-AND-CONSTRAINTS.md#2-как-запрет-обеспечен-в-коде) |
| B-04 | Выс | Одна учётка SQL на чтение и запись; `README`/`SECURITY_AND_DEPLOYMENT` всё ещё говорят «только SELECT» | |
| B-05 | Ср | Приложение создаёт таблицы (`EnsureTables`) — нужны DDL-права, а скрипт прав их не выдаёт; кто создаёт схему — не решено | [09](09-SECURITY-AND-CONSTRAINTS.md#2-как-запрет-обеспечен-в-коде) |
| B-06 | Ср | `sql/copy-prod-to-test.sql` копирует **реальные данные** PROD в TEST без признаков обезличивания; неизвестно, выполнялся ли | |
| B-07 | Ср | Нет rate limiting и antiforgery (допустимо лишь на loopback) | |

### 2.2. Корректность и данные

| № | Серьёзность | Проблема | Подробнее |
|---|---|---|---|
| D-01 | Выс | **Расхождение семантики FOK между Demo и Sql.** Demo блокирует по `NCP.PartInstalled = false`; Sql — по открытым заявкам (`Status = 1`), потому что колонки `PartInstalled` в схеме TEST нет. В Sql закрытая заявка без установленной детали **не заблокирует** FOK (нарушает `SPECIFICATION §16`) | `SqlNcpStore.GetMissingRequiredPartsAsync` |
| D-02 | Выс | В Sql один `Comment nvarchar(50)` на заявку: комментарий оператора и инженера **сливаются/перезаписываются** и обрезаются до 50 символов (в Demo — два поля) | `SqlNcpStore` |
| D-03 | Ср | Строковые значения `Status` в SQL-переходах (`in progress`, `complete`, `FOK`, `rework`) взяты из Demo — надо сверить со справочником реальной базы (В-08) | `SqlPlanTransitions` (`ponytail`) |
| D-04 | Ср | Часовой пояс не согласован (В-06): даты SQL отдаются без зоны, серверное `DateTime.Now` | `API_CONTRACT` |
| D-05 | Ср | Критерий «станция завершена» — рабочий ответ по умолчанию на В-15, не утверждён | `StationChecks` |
| D-06 | Ср | Поиск по последним цифрам VIN — скан таблицы; допущение «VIN всегда с буквами» (подтверждено РП 27.10.2026) | `VinSearch` |
| D-07 | Ср | Demo-состояние единственное на процесс; несколько экземпляров не синхронизируются | |
