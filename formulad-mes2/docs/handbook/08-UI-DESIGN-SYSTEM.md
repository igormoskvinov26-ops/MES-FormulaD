## 1. Принципы и язык форм

Визуальная основа взята из концепта «F7 MES» ([`docs/design/`](../design/), референсные листы дизайна элементов) и промышленного HMI-стиля:

- **Графит + один фирменный красный** (`--f7-red`) как цвет главного действия и акцента. Красный также означает «брак/блокировку» (см. долг П1: сейчас им украшено слишком много).
- **Статус — всегда текст + цвет**, а не только цвет (доступность): бейдж содержит слово, строка таблицы — бейдж «Состояние».
- **Геометрия F7-слоя** (реализовано в `f7-components.css`):
  - контейнеры (панели, плитки, карточки, модалки) — **срезанный правый верхний угол** через `clip-path`;
  - кнопки, теги, бейджи, вкладки, плитки станций — **скос** (параллелограмм) через `clip-path: polygon(...)`;
  - поля ввода — прямоугольные, без скругления (в `.f7plan`);
  - базовый слой `styles.css` по-прежнему скругляет (`--radius-sm/md/lg` = 10/14/22px): сайдбар-пункты, `.table-wrap`, `.card`. Это сознательно не унифицировано (см. долг П3).
- **Два шрифта** плюс моно: Rajdhani (`--font-display`) — заголовки, числа, логотип; Inter — текст интерфейса; `ui-monospace` — VIN/номера (`.mono`).
- **Две темы**: светлая (по умолчанию) и тёмная (`:root[data-theme="dark"]`). Тёмная — основная для цеха по замыслу (не подтверждено кодом, что она выбирается по умолчанию: по умолчанию светлая).

## 3. Архитектура CSS и специфичность

### Два файла, два слоя

| Файл | Роль | Размер (≈) |
|---|---|---|
| [`styles.css`](../../apps/web/src/styles.css) | базовая система: токены, тема, макет, сайдбар, таблицы, формы, статусы, станции, печать, login, отчёты | ~1050 строк |
| [`f7-components.css`](../../apps/web/src/f7-components.css) | «F7-слой» редизайна: компоненты `f7mes__*`, оформление экранов `f7plan__*` и общие переопределения; слой анимации кнопок | ~700 строк |

`styles.css` подключается в `main.tsx`; `f7-components.css` — побочным импортом (`import './f7-components.css'`) в семи файлах: `FokScreen`, `PlanScreen`, `NcpScreen`, `IncomingInspectionScreen`, `ScanTransitionScreen` (для Старт/Завершение/Rework), `StationScreen`, `AdminScreen`. Vite собирает всё в один CSS-файл.

### Именование

- **BEM-подобные префиксы F7-слоя:**
  - `f7mes__*` — компоненты экрана FOK и общие F7-элементы (`f7mes__scan`, `f7mes__slash`, `f7mes__queue-chevron` используются и вне FOK);
  - `f7plan__*` — оформление «табличных» и сканирующих экранов (`f7plan__title`, `f7plan__scanbar`, `f7plan__pager`, `f7plan__tabs`, `f7plan__unit` …);
  - корневой класс `f7plan` (на `div.app`) включает набор переопределений для вложенных базовых классов (`.f7plan .stat-tile`, `.f7plan tbody tr`, `.f7plan .badge` …). Имя историческое: применяется на экранах Plan, NCP, Incoming, Admin, Stations и Start/Complete/Rework.
- Базовый слой — плоские имена (`.stat-tile`, `.state-badge`, `.station-btn`).
- Состояния — `data-*` атрибуты (`data-type="blocked|ready|idle"`, `data-state="done|current|pending|blocked"`, `data-selected="true"`) и модификаторы (`--cut`, `--accent`, `.is-current`, `.active`).

### ⚠ Порядок в бандле и специфичность — главная ловушка

**Факт, проверенный по собранному CSS:** в итоговом бандле правила `f7-components.css` стоят **раньше** `styles.css` (первое правило F7 — позиция ≈345 байт, `.sidebar{` из `styles.css` — ≈25 800). Причина: `main.tsx` импортирует `./App` (а через него экраны и `f7-components.css`) **до** `./styles.css`.

Следствие: при **равной** специфичности выигрывает `styles.css`. Поэтому в F7-слое много «усиленных» селекторов с префиксом `:root`:

```css
/* styles.css: тёмная тема перекрашивает ВСЕ кнопки (специфичность 0,2,1) */
:root[data-theme="dark"] button { background: var(--surface); color: var(--text); border-color: var(--border-strong); }

/* f7-components.css: чтобы класс-кнопка F7 победила (0,3,1) */
:root .f7mes button.f7mes__btn--accent { background: var(--f7-accent); color: #fff; }
```

Правила, из которых это выросло (каждое было пойманным багом):

1. **Глобальное правило тёмной темы `:root[data-theme="dark"] button`** красит любую `<button>` и перебивает одноклассовые селекторы (`.f7mes__btn--accent` = 0,1,0). Симптомы, которые уже видели: пропавший красный фон «Подтвердить FOK», обесцвеченные плитки станций в тёмной теме. Лечение — повышать специфичность (`:root .f7plan .station-btn.station-red`) и/или держать правило ниже по файлу.
2. **`:where(button):hover` в `styles.css`** сделан с нулевой специфичностью специально, чтобы не перебивать одноклассовые кнопки (комментарий в коде). Не заменять на `button:hover`.
3. **Фоновые шорthand-ы.** Многие старые правила пишут `background: ...` (шорthand), который сбрасывает `background-image`/`-size`. Слой анимации кнопок использует `!important` **только** на четырёх longhand-свойствах (`background-image`, `-repeat`, `-position`, `-size`), чтобы никакой шорthand (включая `:root[data-theme="dark"] :where(button):hover:not([disabled])`, специфичность 0,4,0) не обнулял заливку. Цвет основы по-прежнему задаётся обычными правилами.

> **Рекомендация (Н4):** импортировать `f7-components.css` в `main.tsx` **после** `styles.css`. Это перевернёт порядок и позволит убрать значительную часть `:root`-префиксов. Менять только с визуальной регрессией по всем экранам в обеих темах.

### Слой анимации кнопок (последний блок `f7-components.css`)

Сценарий: при наведении цвет «вливается» слева направо.

```css
:root .f7mes button.f7mes__btn, :root .f7plan .controls button, /* … список */ {
  background-image: linear-gradient(var(--fill), var(--fill)) !important;
  background-repeat: no-repeat !important;
  background-position: left center !important;
  background-size: 0% 100% !important;
  transition: background-size .38s cubic-bezier(.22,.61,.36,1), color .12s ease .17s, border-color .2s ease;
}
… :hover:not(:disabled), :focus-visible:not(:disabled) { background-size: 100% 100% !important; }
```

- `--fill` — цвет заливки: у «акцентных» кнопок `--f7-accent-dark` (красная → тёмно-красная), у нейтральных `--f7-red` (серая/белая → красная, текст становится `#fff`).
- Смена цвета текста идёт с задержкой `.17s` и длительностью `.12s`, чтобы белый текст не появлялся на ещё светлой части кнопки.
- Действует на: `button.f7mes__btn`, кнопки в `.f7plan .controls`, `.modal-actions`, `.f7mes__scan button.primary`, пагинацию `.f7plan__pages`, `.station-components`, `.ncp-actions`, вкладки. **Не** действует на пункты сайдбара, плитки, станции, записи очереди.
- Список селекторов — в **двух** местах (объявление `--fill` и применение); новый класс кнопки нужно добавить в оба блока.

## 7. Правила добавления нового компонента

1. **Сначала ищите готовое** в §4. Нужна карточка со срезом — берите `.f7mes__panel--cut`; плитка — `.f7mes__metric`; баннер — `.scan-banner`.
2. **Где писать CSS.** Новый общий компонент — в `f7-components.css`, под комментарием-заголовком секции (`/* ── Название ── */`), с префиксом `f7mes__` (универсальный) или `f7plan__` (оформление экранов). Правки базового поведения (токены, таблицы, формы) — в `styles.css`.
3. **Цвета и размеры — только токены** (`var(--surface)`, `var(--text)`, `var(--st-work)`…), без хардкод-hex. Тёмная тема должна заработать «сама»; если в тёмной нужен отдельный вид — правило `:root[data-theme="dark"] .ваш-класс`.
4. **Кнопки.** Если элемент — `<button>`, проверьте его в тёмной теме: глобальное правило `:root[data-theme="dark"] button` перекрасит его. Усильте специфичность (`:root .f7plan .ваш-класс`) или проверьте порядок. Чтобы кнопка получила заливку при наведении, добавьте селектор в **оба** блока слоя анимации (`--fill` и применение).
5. **`clip-path` — осторожно.** Он отсекает тени и focus-ring (П16, П22). Для новых компонентов предпочитайте маску/псевдоэлемент; если без `clip-path` нельзя, добавьте видимый внутренний фокус.
6. **Размер текста — не меньше 12px**, цели касания — не меньше 44px (идеально 52–56px для действий в цеху).
7. **Состояния — `data-*`/модификаторы**, не inline-стили; цвет всегда дублируйте текстом/значком.
8. **Доступность.** Декоративные символы — `aria-hidden="true"`; интерактивные элементы имеют читаемое имя; не меняйте подписи, на которые опираются тесты (список — [07 §12](07-FRONTEND-GUIDE.md#12-доступность-aria-label-как-контракт-с-тестами)).
9. **`prefers-reduced-motion`.** Любая новая анимация получает отключение в `@media (prefers-reduced-motion: reduce)`.
10. **Проверка.** Запустите стенд (`./stand/stand.sh up`), откройте экран в светлой и тёмной темах, при свёрнутом и развёрнутом сайдбаре, на 1440×900 и 1024×768; затем `npm run test`.
