# AS-IS: подтверждённые факты (проверки 26.10.2026)

Это выдержка из **реального** обследования пользователя, а не новая модель БД.

## Инфраструктура

- ВМ `SQLACCESS`, Windows Server 2019 Standard x64 (Build 17763), Hyper-V/«Microsoft Corporation Virtual Machine».
- 8 логических vCPU, RAM 23.44 GiB (на момент снимка свободно 18.41 GiB).
- C: 255.4 GiB / свободно 209.74 GiB; D: 255.98 GiB / свободно 254.68 GiB.
- SQL Server 2019 Enterprise x64, build 15.0.2170.1, экземпляр `MSSQLSERVER`, БД `FormulaD`.
- Второй процесс `MSSQL$MICROSOFT##WID` — Windows Internal Database, не приложение MES.
- SQL max server memory 20000 MB, min 16 MB; нагрузку в часы пик не измеряли.
- `FormulaD`: recovery FULL, CHECKSUM, ONLINE, MULTI_USER; compatibility 150; Cyrillic_General_CI_AS.
- История `msdb.dbo.backupset` пуста даже по всему SQL серверу; в SQL Agent только системное задание `syspolicy_purge_history`. Резервирование через гипервизор **не подтверждено**. R-001 — критический незакрытый риск.

## SQL структура

- 43 пользовательские таблицы (включая `sysdiagrams`), около 315 записей `tblProductionPlan` на момент инвентаризации, 1205 `tblComponent`, 193 `tblNCP`.
- Один прикладной VIEW `vwImportCheck`, 8 служебных объектов diagram; пользовательских процедур/триггеров в обследованном списке нет.
- 25 FK: единственная связь вне QC-семейства `tblNCP.VIN -> tblProductionPlan.VIN`, 24 FK внутри `tblQC_*`; все активные доверенные, NO_ACTION.
- `tblQC_Products` / `tblQC_ProductPoints` / `tblQC_Events` и связанные таблицы пока пустые, кроме `tblQC_ControlPoints` (6 строк). QC-реестр не имеет FK на `tblProductionPlan`.
- `tblProductionPlan.VIN` PK; ID неуникален на уровне ограничений (при чтении дубли не найдены).

## Access

- Анализировалась **локальная копия** `MES_COPY.accdb`, экспорт `MES_ASIS_20261026_142202(1).zip`.
- 46 форм, 15 отчётов, 29 Access queries, 6 отдельных модулей (включая экспортёр). 31 ODBC linked tables, 3 локальные таблицы.
- Ключевая бизнес-логика в обработчиках VBA форм: импорт плана, сканирование VIN, запуск/завершение сборки, ФОК, несоответствия, печать, входной контроль.
- Конкретные риски: повторный старт VIN может перезаписывать StartDate; импорт не атомарный; общие серверные таблицы tblImportplan/tblPlanTemp для временных операций; ролевой доступ местами реализован скрытием кнопок; код содержит статический PIN; `SQL_backup` — это копирование строк в `*_backup`, а не настоящий SQL backup.
- Наследуемые формы могут содержать старую логику. Не переносить их механически «одна форма — один React экран».

## Неопределённости

Не установлено, какие старые формы реально используются, откуда приходит `tblProductionPlan.ID`, как устроено резервирование гипервизора, возможно ли получить TEST VM, как реализована полноценная промышленная авторизация. Не делать предположений «как будто подтверждено».
