# Безопасность и развёртывание

## Сейчас (MVP 0.1)

- Mac разработчика: локальная DEMO среда, тестовые записи; нет подключений к живому SQL, нет запуска на Windows Server.
- Не коммитить `.env`, secrets, `appsettings.Production.json`, базы, VBA-экспорт, строки подключения, учётные записи.
- `DataSource=Demo` по умолчанию; любая SQL конфигурация без явного TEST marker и защищённой SQL учётной записи должна завершаться fail-closed. Не добавлять код с именем хоста `SQLACCESS` как дефолтной строкой подключения.
- Auth: DEV-only через защищённую явную настройку, без предустановленного пароля. Вне Development нет обхода входа — система закрыта, пока не согласован реальный корпоративный identity-provider.
- TLS localhost dev: подходящие локальные developer certificates. Защищённые cookie только с нужными атрибутами; прод-настройки тестируются отдельно.
- Логи не содержат SQL connection string, PIN, passwords, EngineNumber, полные VIN по умолчанию.

## В перспективе PROD

Один ASP.NET Core app может отдавать статические React assets и API, размещённый как Windows Service на Windows Server 2019 рядом с SQL Server. Это технически возможно, **но не разрешено в этом MVP**.

Блокирующие условия PROD:
- R-001: восстановление `FormulaD` из подтверждённой отдельной резервной копии **не испытано**.
- Не одобрены техническая учётная запись, политка auth, HTTPS, разрешённый порт и сегментация.
- Не выполнена проверка пиковых нагрузок, совместимости с Access, rollback и эксплуатационная приёмка.

Возможность загрузить приложение на сервер сама по себе не является разрешением на ввод в эксплуатацию.
