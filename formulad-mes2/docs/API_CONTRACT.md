# Контракт API v1 — MVP 0.1

Все бизнес-эндпоинты требуют аутентификации. Production API — **только GET**. Base path: `/api/v1`.

## Endpoints

1. `GET /api/v1/health/live` — доступен без аутентификации, `{ "status": "ok" }`, не раскрывает сервер/конфигурацию/БД.
2. `GET /api/v1/production-plan?vin=&status=&page=1&pageSize=25` — страница изделий; `vin` допускает поиск подстроки для таблицы (поведение явно задокументировать), `page=1..`, `pageSize=1..100`, сортировка по VIN ASC по умолчанию. SQL-параметры, никаких конкатенаций запроса.
3. `GET /api/v1/production-plan/{vin}` — точная карточка изделия по первичному ключу VIN; 404 если нет.
4. `GET /api/v1/production-plan/statuses` — доступные статусы из источника (строки как есть, NULL корректно обработать).
5. `GET /api/v1/auth/me` — текущий пользователь/режим; при отсутствии авторизации 401.
6. В Development допускается `POST /api/v1/dev-auth/login` для локального демо. В остальных окружениях этот путь **должен отсутствовать**, а не просто быть скрытым в UI. Использовать секрет из user-secrets/env, никакого встроенного логина/пароля и открытого доступа. После dev-login использовать HTTP-only cookie с защитой от CSRF для stateful auth операции; включить logout аналогично и ограничить CSRF/Origin/host. Вся dev аутентификация разрешена только на loopback.

## Пример ответа списка

```json
{
  "items": [{
    "vin": "DEMO-VIN-00001",
    "id": 1001,
    "modelArticle": "DEMO-800",
    "modelName": "Квадроцикл (демо)",
    "engineNumber": "DEMO-ENG-01",
    "color": "Серый",
    "status": "in progress",
    "statusId": 1,
    "plannedShipmentDate": "2026-11-15T00:00:00",
    "startDate": "2026-10-20T09:00:00",
    "completeDate": null,
    "fokDate": null
  }],
  "page": 1,
  "pageSize": 25,
  "total": 1
}
```

Дата из SQL `datetime` **не содержит зоны**. Не придумывать UTC `Z` для SQL-значений без согласованной политики. Уточнение time zone требуется до PROD.

## Ошибки

- 400: неправильная длина VIN, отрицательная страница, pageSize вне 1..100 (ProblemDetails с понятным `title`).
- 401: нет авторизации; 403: нет полномочий; 404: VIN отсутствует; 500: внутреннее исключение скрыто от пользователя, trace ID для поддержки.
- Для health отдельные правила; секреты, ODBC и адрес SQL не возвращать.
- На API запрещены `POST/PUT/PATCH/DELETE` по производственным сущностям.
